# Phase 1 手動E2Eチェックリスト

前提: `npm run build` → `chrome://extensions` で「パッケージ化されていない拡張機能を読み込む」→ `dist/` を選択。
テスト用に**削除してよいノートブック**を複数用意すること（削除は取り消し不可）。

## 表示・注入
- [ ] `https://notebook.google.com/` を開くと各行の先頭にチェックボックスが出る。
- [ ] 上部にスティッキーのアクションバーが出て、スクロールしても追従する。
- [ ] 一覧を再読込/フィルタ切替しても、チェックボックスが二重注入されない。
- [ ] ノートブックをリネームすると、その行のチェックボックスの `aria-label` と選択キー（`data-nlk-checkbox` 属性）が新タイトルに追従する（リネームは監視対象コンテナ内ではタイトルテキストのみの characterData 変化になり得るため、issue #28 の発火条件の実機確認を兼ねる）。リネーム前に付けていたチェックは外れる（旧タイトルのキーは選択件数に残留し得る。「すべて解除」で復旧。既知の title 識別トレードオフ）。

## カード（グリッド）表示（issue #66）
- [ ] 右上のアイコンでカード表示に切り替えると、各カードの3点メニューの**左**にチェックボックスが出る。
- [ ] おすすめ（Reader ロール）カードにはチェックボックスが出ない（2026-10-04 以降、3点メニューは**有る**が「削除」項目が無い。requirements.md §8.14）。
- [ ] 同名のノートブックが 2 件あるとき、片方だけチェックすると「1件選択中」になり、もう片方はチェックされない。削除しても選んだ方だけが消える（ID 識別。requirements.md §8.14）。
- [ ] 一覧（リスト）表示でチェックボックスがタイトルと同じ行に並び、行の高さが他の行と揃っている。
- [ ] 所有ノートブックと同名のおすすめノートブックがあっても、所有側だけが削除される（おすすめ側のメニューが開いて止まらない）。
- [ ] チェックボックスをクリックしてもノートブックが開かない（カード遷移しない）＆トグルできる。
- [ ] カードで数件選択 → 一覧（リスト）表示へ切替 → 選択が維持される（逆方向も）。
- [ ] カード表示で選択 → 一括削除（メニュー→削除→確認）が正常に動く。

## 選択
- [ ] 個別チェックで「N件選択中」が更新される。
- [ ] 「すべて選択」で全行が選択され、件数が全件になる。
- [ ] 「すべて解除」で 0 件になり、削除ボタンが無効化される。

## 削除（少数）
- [ ] 2〜3件選択 → 「選択したN件を削除」→ 通常確認が出る。
- [ ] 確認 → 1件ずつ削除され、進捗が更新され、対象行が消える。

## 削除（大量 / 全選択）
- [ ] 10件以上 or 全選択で「件数タイプ確認」が出る。
- [ ] 誤った件数を入力すると [削除] が無効のまま。
- [ ] 正しい件数入力で [削除] が有効化 → 削除実行。

## 異常系
- [ ] 削除中にネットワーク/DOM が想定外でも拡張がクラッシュせず、エラー表示で停止する。
- [ ] 失敗が出た場合、成功分のみ選択解除され、「失敗のため停止: 成功 N件 / 失敗 1件 / 残り M件は未処理」と表示される（「完了: …」ではない。残りが未処理であることが分かる。issue #99）。
- [ ] 削除中に「中断」を押すと、処理中の1件完了後に停止する。
- [ ] 既知のエッジケース（**ノートブック ID を取れない DOM にフォールバックした場合のみ**。2026-10-04 時点の実機は全行 ID あり。requirements.md §8.14）: 選択キーがタイトルになり、同名タイトルのノートブックが複数あると区別できず、一方を選択・削除すると両方に影響し得る。典型例は「無題のノートブック」（Untitled）が複数ある場合。チェックボックスの `data-nlk-checkbox` 属性が `title:` で始まっていたらこの状態なので、同名が並ぶ状況での一括削除は避けること。
